# 01 · 架构与目录规范

## 1. 总体架构

```
┌──────────────────────────── apps/web (@repo/web, FSD) ────────────────────────────┐
│  app  →  pages  →  widgets  →  features  →  entities  →  shared                    │
│  (装配)   (页面)    (布局壳)     (交互特性)    (业务实体)    (通用基建)                │
└───────────────────────────────┬───────────────────────────────────────────────────┘
                                │ workspace:* （消费 dist 产物）
                ┌───────────────┴───────────────┐
                │ packages/ui (@repo/ui)        │ packages/utils (@repo/utils)
                │ Vite lib + vue-tsc d.ts       │ tsup (esm+cjs+dts)
                │ Element Plus 显式按需再导出    │ 纯 TS，零框架依赖
                └───────────────────────────────┘
```

约束：**单向依赖**。箭头只能从上层指向下层；`shared` 不依赖任何上层；`packages/*` 不依赖 `apps/*`。

## 2. Monorepo 布局

| 位置             | 包名          | 职责                                        | 构建方式                   |
| ---------------- | ------------- | ------------------------------------------- | -------------------------- |
| `apps/web`       | `@repo/web`   | 主应用，FSD 分层                            | Vite 8 应用构建            |
| `packages/utils` | `@repo/utils` | 通用纯函数、存储封装、色阶算法、树/路由工具 | tsup 8.5.1                 |
| `packages/ui`    | `@repo/ui`    | Element Plus 二次封装组件、指令、组合式函数 | Vite lib + vite-plugin-dts |

> `packages/utils` **不得**依赖 Vue/Element Plus（保持纯 TS，便于在 Node 环境测试）。
> `packages/ui` 可依赖 Vue + Element Plus + `@repo/utils`。

## 3. FSD 分层定义

采用「精简 FSD」：`app / pages / widgets / features / entities / shared`。
**不引入 `processes` 层**（官方已废弃，其职责上移到 `app` 与 `features`）。

| 层         | 放什么                                                                                                      | 不放什么                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `app`      | 入口 `main.ts`、`App.vue`、路由实例与守卫、Pinia 实例、provider 装配（i18n / EP / MSW）、全局样式与主题令牌 | 业务组件、页面                                    |
| `pages`    | 路由页面组件（一个路由一个目录），只做组合与布局拼装                                                        | 复杂业务逻辑（下沉到 features）                   |
| `widgets`  | 大块 UI 组合体：AppLayout 系列、菜单树、Header、Tabs、Breadcrumb                                            | 与具体业务实体强绑定的逻辑                        |
| `features` | 完整用户交互：登录、主题切换、布局切换、语言切换、Tabs 操作                                                 | 无交互的纯展示片段（放 shared/ui 或 entities/ui） |
| `entities` | 业务实体：user、menu、permission（类型 + store + 只读逻辑）                                                 | 跨实体的编排（放 features）                       |
| `shared`   | 与业务无关：ui 基础件、lib 工具、api 客户端、config、i18n、types、assets                                    | 任何业务语义                                      |

## 4. Slice 内部结构（统一约定）

每个 slice 目录内按「技术目的」分目录，且**必须提供 Public API 出口** `index.ts`：

```
features/theme-switch/
├─ index.ts          # Public API：只导出外部允许使用的东西
├─ model/            # store / 状态 / 类型 / 纯逻辑
│  ├─ theme.store.ts
│  └─ types.ts
├─ ui/               # 该特性私有组件
│  └─ ThemeSwitch.vue
├─ lib/              # 该特性私有工具
│  └─ apply-theme.ts
└─ api/              # 该特性私有请求（可选）
```

命名规范：

- 目录：`kebab-case`（`theme-switch`）
- 组件文件：`PascalCase.vue`（`ThemeSwitch.vue`）
- 组合式函数：`useXxx.ts`（`useTheme.ts`），导出 `useXxx()`
- Store：`xxx.store.ts`，导出 `useXxxStore`（`useThemeStore`）
- 类型：`types.ts` 或 `xxx.types.ts`，导出 `interface Xxx`（不加 `I` 前缀）
- 常量：`xxx.constants.ts`，全大写 `SCREAMING_SNAKE_CASE`
- CSS 类名：**BEM**（`block` / `block__element` / `block--modifier`，词间 kebab-case，如 `fsd-table__pagination`）；`stylelint.config.js` 的 `selector-class-pattern` 已按此放行
- 私有实现默认**不导出**到 `index.ts`

## 5. 导入规则（硬性）

1. **同层禁止互相导入**：`features/auth` 不能导入 `features/theme-switch`；需要协作时上提到 `pages` 或 `app` 编排。
2. **只能向下导入**：`pages → widgets/features/entities/shared` ✅；`entities → features` ❌。
3. **只能经 Public API 导入**：
   ```ts
   // ✅
   import { useThemeStore } from '@/features/theme-switch'
   // ❌ 禁止穿透到内部实现
   import { useThemeStore } from '@/features/theme-switch/model/theme.store'
   ```
4. **`shared` 不得导入任何上层**；`entities` 不得导入 `features/pages/widgets`。
5. **跨包导入**：应用只能 `import ... from '@repo/ui'` / `'@repo/utils'`，禁止深路径 `@repo/ui/dist/...`。

> 建议用 ESLint `import/no-restricted-paths`（或自定义 `no-restricted-imports` 规则）把 2/3/4 落成自动检查，详见 `docs/06`。

```

│  │  ├─ mock.ts                # MSW 启动（仅 dev 且开关开启）

│  ├─ router/

│  │  ├─ constant-routes.ts     # /login /404 /403 / 根布局

├─ widgets/

│     ├─ index.ts

│     ├─ SidebarLayout.vue / TopLayout.vue / MixLayout.vue / DualLayout.vue

   ├─ ui/                       # 基于 @repo/ui 的再封装（若有）
   ├─ lib/                      # color/tree/route 工具（可由 @repo/utils 转出）

   └─ assets/
```

## 7. 常见反例（评审时直接打回）

- 在 `shared/` 里 import `@/entities/user`（反向依赖）
- 页面直接 `import { ElTable } from 'element-plus'`（应统一从 `@repo/ui` 或 `shared/ui` 出）
- 在 `widgets/layout` 里写登录逻辑（应抽到 `features/auth`）
- 组件里直接 `localStorage.setItem`（应走 `@repo/utils` 的 `storage`）
- 颜色/间距硬编码（应走 CSS 变量令牌，Stylelint `declaration-strict-value` 会在提交与 CI 拦截，见 `docs/06` §5）
