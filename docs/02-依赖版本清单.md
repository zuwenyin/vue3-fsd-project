实测结论（本机 Node `v24.19.0`，`process.versions.modules = 137`）：

- **`node:sqlite` 内置模块可直接加载**，无需 `--experimental-sqlite` 标志，导出 `{ DatabaseSync, StatementSync, Session, constants, backup }` → 可作为 `better-sqlite3` 的**零编译回退方案**。注意 `apps/server` 是 ESM（`"type": "module"`），需 `createRequire(import.meta.url)('node:sqlite')`（见 `docs/11` §3.2）。
- `better-sqlite3@13.0.3` 声明 `engines.node >= 22`，但需与 ABI **137** 匹配的 prebuild；若 `pnpm install` 触发源码编译，Windows 需 VS Build Tools + Python 3.11+。失败即切 `node:sqlite`（DAO 层已隔离，见 `docs/11` §3）。

## 6. TypeScript 版本决策（重要）

- `typescript@latest = 7.0.2`，但 `typescript-eslint@8.70.1` 的 peer 为 `>=4.8.4 <6.1.0`，**TS 7 会产生 peer 不满足告警**（且 TS 7 为原生重写版，生态适配仍在推进）。
- 可选稳定版：`5.9.3`（5.x 末版）、`6.0.3`（6.x stable）。
- **结论：采用 TypeScript 6.0.3** —— 既非保守旧版，又被 `typescript-eslint` / `vue-tsc` 完整支持，安装零 peer 告警。
- 后续若 `typescript-eslint` 发布支持 TS 7 的主版本，再统一升级（升级前需跑通 `type-check` + `lint` + `test`）。
- ⚠️ **与 oxlint 的耦合**：oxlint 的 type-aware 能力底层是 `tsgo`，**要求 TypeScript 7.0+**。因此「升级 TS 7」与「切换到 oxlint 做类型感知 lint」是同一个决策，必须一起评估。当前已决定**保持 ESLint 10 + TS 6.0.3**，oxlint 暂缓（见 `docs/06` §13）。

## 7. 版本收敛方式：pnpm Catalog（推荐）

在 `pnpm-workspace.yaml` 中集中声明版本，各包用 `catalog:` 引用，避免多包版本漂移。

> **唯一权威 catalog 见 `docs/10` §1.1**（含前端 + 后端 + 测试 + 质量全部条目）。本节的示例与 §5.5 的追加块是**分类说明**，照抄容易漏项；实施时以 `docs/10` §1.1 为准。

## 8. 兼容性风险与对策

| 风险                                                    | 影响                             | 对策                                                                                                                                                                                                      |
| ------------------------------------------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vite 8 为较新大版本，插件生态可能滞后                   | 构建插件报错                     | 只用官方插件（`@vitejs/plugin-vue`），避免社区 Vite 插件；确需时先做小样验证                                                                                                                              |
| `vue-router` 5.x / `pinia` 4.x 相对 4.x/2.x 有 API 变化 | 写法不兼容旧教程                 | 实施时以官方文档为准；路由守卫、store 写法先写最小 demo 验证                                                                                                                                              |
| `sass` 1.x 弃用 `@import`                               | 编译告警                         | 一律使用 `@use` / `@forward`                                                                                                                                                                              |
| TS 6 与新语法差异                                       | 极少                             | 锁 `@vue/tsconfig` 预设，不自定义激进编译选项                                                                                                                                                             |
| 子包为 dist 产物消费                                    | HMR/调试链路变长                 | 子包 `dev` 脚本为 watch 构建；必要时 dev 环境主应用 alias 直连源码（见 `docs/05`）                                                                                                                        |
| `better-sqlite3` 原生模块编译                           | Windows/Linux 无工具链时安装失败 | ① 根 `package.json` 的 `pnpm.onlyBuiltDependencies: ["better-sqlite3"]`（pnpm 10+ 推荐位置）；② 优先用 prebuild（ABI 137）；③ 失败即切 Node 内置 `node:sqlite`（已实测可用），DAO 层适配见 `docs/11` §3.2 |

## 9. 升级策略

1. 每月执行一次 `pnpm outdated -r`，只在**非破坏性**范围内升级（patch/minor）。
2. 大版本升级单独开分支，需通过：`type-check` + `lint` + `test` + `build` + 手工冒烟（登录 / 路由 / 主题 / 布局切换 / Tabs）。
3. 升级后同步更新本文档的实测版本表（标注查询日期）。
