# 03 · 动态路由与权限

> 方案：**后端下发路由树 → 前端映射组件 → 运行时 `addRoute` 注册 → 生成菜单树**。
> 前端只保留「常量路由」（登录、根布局、404、403），其余全部动态注入。

## 1. 后端契约（生产者：`apps/server`，见 `docs/11` §4；字段已固化）

```ts
// GET /api/user/routes  →  { data: RouteNode[] }
interface BackendRouteNode {
  id: number | string
  parentId: number | string | null
  /** 路由唯一名，同时作为 Tabs/keep-alive 的 key */
  name: string
  /** 子路由为相对路径；顶级建议以 '/' 开头 */
  path: string
  redirect?: string
  /** 组件定位：'system/user/index'（相对 src/pages）；'Layout' 表示布局容器 */
  component?: string
  meta: {
    title: string // 菜单标题（回落值）
    titleKey?: string // i18n key，有 i18n 时优先；**本期不接 vue-i18n**，仅保留字段，回落逻辑见 docs/13 §3.4.1 的 resolveMenuTitle()（决策 D2）
    icon?: string // 图标名（映射到 @element-plus/icons-vue）
    order?: number // 排序
    keepAlive?: boolean // 是否缓存（默认 true）
    hideInMenu?: boolean // 注册但不显示
    hideChildrenInMenu?: boolean
    activePath?: string // 详情页高亮父菜单
    external?: boolean // 外链
    roles?: string[]
    permissions?: string[]
    affix?: boolean // Tabs 固定
    layout?: 'sidebar' | 'top' | 'mix' | 'dual' // 可选：指定布局，缺省跟随全局
  }
  children?: BackendRouteNode[]
}
```

组件路径约定（**唯一约定，必须前后端一致**）：

| backend `component` | 实际文件                                           |
| ------------------- | -------------------------------------------------- |
| `Layout`            | `widgets/layout/AppLayout.vue`（常量路由里的父级） |
| `system/user/index` | `src/pages/system/user/index.vue`                  |
| `dashboard/index`   | `src/pages/dashboard/index.vue`                    |

> 契约生产者：`apps/server`（Express + SQLite），生成规则见 `docs/11` §5.3。补充约定：
>
> - `component` 为空 = **纯分组目录节点**；若该节点无子节点，后端不下发该节点。
> - `meta.roles` / `meta.permissions` 为空数组时后端**不写入 meta**，避免前端误判为「需要权限」。
> - 管理视图（菜单配置页）读写的是**同一张表**的扁平记录，见 `docs/14` §2。

## 2. 常量路由（前端静态）

```ts
// app/router/constant-routes.ts
export const LAYOUT_ROUTE_NAME = 'Layout'

export const constantRoutes: RouteRecordRaw[] = [
  {
    path: '/login',
    name: 'Login',
    component: () => import('@/pages/login/index.vue'), // 或 features/auth/ui/LoginPage.vue
    meta: { title: '登录', hideInMenu: true, public: true },
  },
  {
    path: '/',
    name: LAYOUT_ROUTE_NAME,
    component: () => import('@/widgets/layout/AppLayout.vue'),
    redirect: '/dashboard',
    children: [], // 动态路由挂载到这里
  },
  {
    path: '/403',
    name: 'Forbidden',
    component: () => import('@/pages/error/403.vue'),
    meta: { public: true },
  },
  {
    path: '/:pathMatch(.*)*',
    name: 'NotFound',
    component: () => import('@/pages/error/404.vue'),
    meta: { public: true },
  },
]
```

> 404 必须最后注册。动态路由一律 `addRoute(LAYOUT_ROUTE_NAME, record)` 挂到 `Layout` **之下**，顶层通配 404 不会被覆盖，**注册后无需重排、也无需重新追加 404**（与 `docs/13` §3.1 一致）。

## 3. 组件映射（import.meta.glob）

```ts
// shared/lib/page-modules.ts（★ 实际位置；app/router/dynamic.ts 与 features 均从此导入）
import type { Component } from 'vue'
import LAYOUT from '@/widgets/layout/AppLayout.vue'

const pageModules = import.meta.glob<Component>('/src/pages/**/*.vue')

/** 组件路径白名单，供菜单配置页下拉使用（docs/14 §4.4） */
export const pageComponentKeys: string[] = Object.keys(pageModules)
  .map((k) => k.replace(/^\/src\/pages\//, '').replace(/\.vue$/, ''))
  .sort()

export function resolvePageComponent(component?: string): Component | undefined {
  if (!component) return undefined
  if (component === 'Layout') return LAYOUT
  const key = `/src/pages/${component.replace(/^\/+/, '')}.vue`
  const loader = pageModules[key]
  if (!loader) {
    console.error(`[router] 未找到组件: ${component} → ${key}`)
    return undefined
  }
  return loader // 懒加载函数，可直接作为 component
}
```

> **为什么放 `shared`**：菜单配置页（`features/menu-management`）需要使用 `pageComponentKeys`，若放在 `app/` 会形成 `features → app` 的向上依赖，违反 `docs/01` §5。

要点：

- `import.meta.glob` 的 key 用**绝对路径** `/src/pages/**/*.vue`（不依赖 alias，编译期确定）。
- 未命中时：开发环境直接报错提示，生产环境降级为 404 组件并上报。
- 组件懒加载由 glob 自动生成 `() => import(...)`，天然代码分割。

## 4. 注册流程

```
登录成功（拿到 token）
  └─► router.beforeEach
       ├─ 未登录 & 非 public → /login
       ├─ 已登录 & 未加载路由 →
       │    1. 拉取 /api/user/routes
       │    2. filterRoutes(nodes, permissions, roles)   // 路由级过滤
       │    3. resolvePageComponent 映射 + 规范化 path
       │    4. router.addRoute('Layout', record)     // 逐个挂载到布局下
       │    5. 保存 menuTree 到 entities/menu store
       │    6. next({ ...to, replace: true })        // 重新进入，确保匹配
       └─ 已加载 → 进入业务处理（标题、Tabs 记录、权限点校验）
```

```ts
// app/router/guard.ts 关键片段
let routesLoaded = false

router.beforeEach(async (to) => {
  const auth = useUserStore() // 决策 D8：token / roles / permissions 唯一归 entities/user
  if (to.meta.public) return true

  if (!auth.token) return { name: 'Login', query: { redirect: to.fullPath } }

  if (!routesLoaded) {
    try {
      const nodes = await fetchUserRoutes()
      const accessible = filterRoutes(nodes, auth.permissions, auth.roles)
      accessible.forEach((r) => router.addRoute(LAYOUT_ROUTE_NAME, r))
      useMenuStore().setTree(buildMenuTree(accessible))
      routesLoaded = true
      return { ...to, replace: true }
    } catch {
      await logout() // features/auth 编排：清 token + clearDynamicRoutes + 复位（docs/13 §3.6）
      return { name: 'Login' }
    }
  }
  return true
})
```

**登出 / 切换账号**时必须清理：移除动态路由 + 清空 store + `routesLoaded = false`。

**已定方案：热替换（精确 `removeRoute`）**，不再考虑重建 router 实例——原因是热替换可被菜单配置页复用，且不丢当前页面状态。实现上由 `app/router/dynamic.ts` 维护 `dynamicRouteNames: Set<string>`：

```ts
export function clearDynamicRoutes(router: Router) {
  dynamicRouteNames.forEach((name) => router.hasRoute(name) && router.removeRoute(name))
  dynamicRouteNames.clear()
}
```

## 5. 菜单树生成

- 菜单树与路由树**同源不同形**：由 `entities/menu/lib/build-tree.ts` 从路由记录派生。
- 过滤规则：`hideInMenu` 移除；`hideChildrenInMenu` 时把子节点提升到当前层；只有一个可见子节点的父节点自动「折叠为单节点」。
- 排序：`meta.order` 升序，缺省按返回顺序。
- 高亮：`meta.activePath` 用于详情页回指父菜单。

```ts
// entities/menu/model/types.ts
interface MenuItem {
  key: string // route.name
  path: string
  title: string // 已回落后的标题（渲染前仍建议再走一次 resolveMenuTitle）
  titleKey?: string // 决策 D2：i18n key，P7 接入后生效
  icon?: string
  children?: MenuItem[]
  affix?: boolean
}
```

## 6. 权限模型

| 层级   | 实现                                                                | 位置                                            |
| ------ | ------------------------------------------------------------------- | ----------------------------------------------- |
| 路由级 | `filterRoutes()`：按 `meta.roles` / `meta.permissions` 过滤整棵子树 | `entities/permission`                           |
| 按钮级 | 指令 `v-permission="'system:user:add'"` + 函数 `hasPermission()`    | `entities/permission` + `shared/lib/directives` |
| 接口级 | axios 响应拦截：401 → 登出跳转；403 → 全局提示                      | `shared/api`                                    |

```ts
// entities/permission/lib/has-permission.ts
export function hasPermission(
  need?: string | string[],
  owned: string[] = [],
  roles: string[] = [],
) {
  if (!need || (Array.isArray(need) && need.length === 0)) return true
  if (roles.includes('admin')) return true
  const list = Array.isArray(need) ? need : [need]
  return list.some((p) => owned.includes(p))
}
```

> 前端过滤只是**体验层**，后端必须做最终鉴权（文档中需注明）。

## 7. 与布局模式的关系

- 布局模式是**全局用户偏好**（`features/layout-switch` 的 store），四种模式共用同一份 `menuTree`。
- 各个布局组件决定如何消费这棵树：
  - `sidebar`：整棵树 → 左侧 `FsdMenu`（可折叠；`el-menu` 系列一律由 `@repo/ui` 封装，见决策 D7）
  - `top`：一级 → 顶部水平菜单，其余走 `FsdSubMenu` 下拉
  - `mix`：顶部渲染一级，选中后左侧渲染其子树
  - `dual`：左侧窄条渲染一级，右侧子侧栏渲染子树
- `meta.layout` 可选：某条路由强制指定布局时，路由进入时临时覆盖全局模式（可选能力，实施阶段确认）。

## 8. 验收标准

- [ ] 后端返回 3 级路由时，四种布局下菜单与面包屑均正确
- [ ] 无权限的路由被过滤，直接访问 URL 跳转到 403/404
- [ ] 刷新页面后动态路由重建成功（不白屏、不落入 404）
- [ ] 登出后动态路由被清理，切换低权限账号不残留旧路由
- [ ] 后端返回的 `component` 拼错时，开发环境有明确报错且不崩溃
- [ ] 菜单配置页（P3.5）改动后点「应用变更」，路由表与侧边栏即时刷新，当前页失效时安全跳转（`docs/14` §5.2）
