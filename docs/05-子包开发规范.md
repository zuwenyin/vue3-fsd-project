# 05 · 子包开发规范

> 两个子包：`@repo/utils`（tsup）与 `@repo/ui`（Vite lib + vite-plugin-dts）。
> **消费方式：打包产物**（`dist` + `d.ts`），主应用通过 `workspace:*` 依赖。

## 1. 通用约定

| 项        | 约定                                                                        |
| --------- | --------------------------------------------------------------------------- |
| 包目录    | `packages/utils`、`packages/ui`                                             |
| 包名      | `@repo/utils`、`@repo/ui`（`private: false`，可发布）                       |
| 入口      | `src/index.ts`（唯一 Public API 出口）                                      |
| 产物      | `dist/`（`index.mjs`、`index.cjs`、`index.d.ts`）                           |
| 副作用    | `package.json` 声明 `"sideEffects": false`（`@repo/ui` 若有全局样式则列出） |
| 依赖      | `peerDependencies` 声明 `vue` / `element-plus`；主应用负责安装              |
| Node 版本 | 与根一致（`>=22.12.0`）                                                     |

统一 `exports` 形态：

```json
{
  "name": "@repo/ui",
  "version": "0.0.0",
  "type": "module",
  "sideEffects": ["**/*.css"],
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    },
    "./styles.css": "./dist/style.css"
  },
  "files": ["dist"],
  "scripts": {
    "dev": "vite build --watch",
    "build": "vite build",
    "type-check": "vue-tsc --noEmit",
    "test": "vitest run"
  }
}
```

## 2. @repo/utils

### 结构

```
packages/utils/
├─ src/
│  ├─ index.ts           # 统一出口
│  ├─ storage/           # localStorage 封装（命名空间/过期/类型安全）
│  ├─ color/             # hexToRgb / mix / generatePrimaryShades
│  ├─ tree/              # 树遍历、查找、过滤、映射（菜单/路由复用）
│  ├─ is/                # 类型判断
│  ├─ format/            # 时间、金额、脱敏
│  └─ request/           # 与框架无关的 fetch 工具（可选）
├─ tsup.config.ts
├─ package.json
└─ tsconfig.json
```

### tsup 配置

```ts
// packages/utils/tsup.config.ts
import { defineConfig } from 'tsup'

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm', 'cjs'],
  dts: true,
  sourcemap: true,
  clean: true,
  treeshake: true,
  target: 'es2022',
  outExtension: ({ format }) => ({ js: format === 'esm' ? '.mjs' : '.cjs' }),
})
```

### 约束

- **零框架依赖**：不 import `vue`、`element-plus`（保证可在 Node/测试中直接使用）。
- 导出的函数必须**纯函数优先**，副作用集中在 `storage` 等明确模块。
- `color/shades.ts`、`tree/*` 必须有单测（主题与路由的正确性依赖它们）。
- 覆盖率目标：**语句 ≥ 90%**。

## 3. @repo/ui

### 定位

Element Plus 的**二次封装层**：统一尺寸、统一空状态、统一表单校验提示、统一主题变量消费。
主应用**不直接** `import { ElXxx } from 'element-plus'`，一律从 `@repo/ui` 获取。

### 结构

```
packages/ui/
├─ src/
│  ├─ index.ts               # 出口：组件 + 类型 + 安装函数
│  ├─ components/
│  │  ├─ FsdTable/index.ts + FsdTable.vue   # 表格：分页/loading/空态/树形（expose bodyRef）
│  │  ├─ FsdForm/...                        # 含 FsdFormItem
│  │  ├─ FsdDialog/...
│  │  ├─ FsdButton/...
│  │  ├─ FsdIcon/...                        # 统一图标（映射 @element-plus/icons-vue）
│  │  ├─ FsdSelect/...                      # el-select 再导出
│  │  ├─ FsdTreeSelect/...                  # el-tree-select 再导出
│  │  ├─ FsdTag/...                         # 状态标签
│  │  ├─ FsdSwitch/...                      # 布尔开关
│  │  ├─ FsdMenu/...                        # el-menu / el-sub-menu / el-menu-item 再导出
│  │  └─ FsdColorPicker/...                 # el-color-picker 再导出
│  ├─ composables/
│  ├─ directives/
│  ├─ types/
│  └─ styles/index.scss
├─ vite.config.ts
└─ package.json
```

### Element Plus 引入规则（已确认：显式按需）

- 在组件内**显式 import 用到的 EP 组件与样式**，不引入全量包、不使用 `unplugin-vue-components`：
  ```vue
  <script setup lang="ts">
  import { ElTable, ElTableColumn, ElPagination } from 'element-plus'
  // ★ 样式必须一起 import：只引组件不引样式 → 组件裸奔（图标被撑成巨幅、按钮/输入框无样式）
  import 'element-plus/es/components/table/style/css'
  import 'element-plus/es/components/pagination/style/css'
  </script>
  ```
  - 每个 `style/css` 入口会自带依赖样式（如 `select` → `option`/`popper`/`scrollbar`），无需逐个子组件重复引入；`el-icon` 的 `svg{width:1em}` 尺寸规则在 `base.css`，由任一入口带入。
  - **实施教训（P3 修复）**：`@repo/ui` 初期只 import 了 EP 组件、漏了样式，登录页/侧边栏图标被撑成数百 px。EP 的 `package.json` 已声明 `sideEffects: ["es/components/*/style/*"]`，按需样式在打包时会被正确保留，勿再改成 `sideEffects: false`。
- 同一个 EP 组件的 import 只允许出现在 `@repo/ui` 内，主应用不得重复引入；**例外**是主应用直接用到的反馈类组件（当前只有 `ElMessage`，见 `shared/api/request.ts` 与登录页）——此时必须在 `app/providers/element.ts` 同时 `import 'element-plus/es/components/message/style/css'`。
- 单测（Vitest）中 EP 按需样式入口会被根目录的 `vitest.element-plus-style-stub.ts` 插件替换为空模块：否则 Node 原生加载 `.css` 会报 `Unknown file extension ".css"`；也不要改用 `server.deps.inline: ['element-plus']`（ui 测试耗时 10s → 53s）。
- **没有 EP 组件**能在主应用直接使用：`FsdMenu` / `FsdColorPicker` 等同理，一律在本包内再导出（决策 D7；完整清单与最小 props 见 `docs/10` §2.2 / §2.2.1）。
- 需要 EP 全局配置（尺寸、语言、zIndex）时，由主应用 `app/providers/element.ts` 通过 `<ElConfigProvider>` 或 `app.use(ElementPlus, {...})` 提供；**倾向 `ElConfigProvider` 包裹 + 局部组件引入**（最终在 P2 实施时定，见 `docs/07` 待定项）。

### Vite lib 构建配置

```ts
// packages/ui/vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import dts from 'vite-plugin-dts'
import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  plugins: [vue(), dts({ entryRoot: 'src', outDir: 'dist', tsconfigPath: './tsconfig.json' })],
  build: {
    lib: {
      entry: fileURLToPath(new URL('src/index.ts', import.meta.url)),
      name: 'RepoUI',
      fileName: 'index',
    },
    rollupOptions: {
      external: ['vue', 'element-plus', '@element-plus/icons-vue', /^element-plus\/.*/],
      output: { globals: { vue: 'Vue', 'element-plus': 'ElementPlus' } },
    },
    cssCodeSplit: false,
    sourcemap: true,
  },
})
```

- `external` 必须外置 `vue` / `element-plus`，否则主应用会出现双实例。
- 类型产物：优先 `vite-plugin-dts` 5.1.1；若 `.vue` 声明异常，兜底用
  `vue-tsc -p tsconfig.build.json --declaration --emitDeclarationOnly --outDir dist`。
- 构建后自检：`dist/index.d.ts` 存在且能被主应用 `type-check` 命中。

## 5. 开发流程（产物消费下的 DX）

```bash
# 一次性构建子包
pnpm -r --filter "@repo/utils" --filter "@repo/ui" run build

# 并行 watch 构建 + 主应用 dev（推荐日常使用）
pnpm -r --parallel --filter "@repo/*" run dev
```

注意：

- 并行启动时主应用可能先于 `dist` 生成而报「模块不存在」——先跑一次 `build`，或等 watch 首次产出后 Vite 会自动重新预构建。
- 依赖更新后若类型未刷新，执行根级 `pnpm type-check` 确认 `dist/index.d.ts` 已更新。
- **可选 DX 优化（待你确认）**：在 `apps/web/vite.config.ts` 中仅在 `command === 'serve'` 时把 `@repo/ui`、`@repo/utils` alias 指向 `packages/*/src`，实现源码级 HMR；`build` 与 CI 仍走产物。两者不冲突，但需要保证源码与产物行为一致。

## 6. 版本与发布（Changesets）

- 子包改动必须带 changeset：`pnpm changeset`（选择 `@repo/ui` / `@repo/utils`，选 minor/patch）。
- 版本应用：`pnpm version-packages`（自动升版本 + 写 CHANGELOG）。
- 发布：`pnpm release`（`pnpm -r publish --access public`）。
- 未发布前，`workspace:*` 保证主应用始终使用本地包。

## 7. 新增子包的流程（后续扩展用）

1. `packages/<name>` 建目录，`package.json` name 使用 `@repo/<name>` 作用域。
2. 按本文档 §1 配置 `exports` / `files` / `scripts`。
3. 选择构建器：纯 TS → tsup；含 `.vue` → Vite lib + dts。
4. 根 `pnpm-workspace.yaml` 已含 `packages/*`，无需修改；执行 `pnpm install` 建立链接。
5. 补 `README.md` 与单测，并在根 README 的子包表中登记。
