## 2. 根 package.json

```json
{
  "name": "vue3-fsd-project",
  "private": true,
  "packageManager": "pnpm@11.9.0",
  "engines": { "node": ">=22.12.0" },
  "scripts": {
    "dev": "pnpm -r --parallel --filter \"@repo/*\" run dev",
    "dev:web": "pnpm --filter @repo/web run dev",
    "dev:server": "pnpm --filter @repo/server run dev",
    "db:reset": "pnpm --filter @repo/server run db:reset",
    "build": "pnpm -r --filter \"@repo/*\" run build",
    "lint": "pnpm lint:js && pnpm lint:style",
    "lint:js": "eslint . --max-warnings 0",
    "lint:style": "stylelint \"**/*.{css,scss,vue}\" --cache --max-warnings 0",
    "lint:fix": "eslint . --fix && stylelint \"**/*.{css,scss,vue}\" --fix",
    "format": "prettier --write .",
    "type-check": "pnpm -r run type-check",
    "test": "pnpm -r run test",
    "test:cov": "pnpm -r run test:cov",
    "changeset": "changeset",
    "version-packages": "changeset version",
    "release": "pnpm -r publish --access public",
    "prepare": "husky"
  }
}
```

> **pnpm 11 变更**：构建脚本白名单**不再**读取根 `package.json` 的 `pnpm` 字段（`onlyBuiltDependencies` 已被移除），
> 必须写在 `pnpm-workspace.yaml` 的 `allowBuilds`（实测：写在 `package.json` 时 pnpm 会打印 WARN 并忽略，`pnpm install` 退出码为 1）：
>
> ```yaml
> allowBuilds:
>   esbuild: true
>   '@parcel/watcher': true
>   better-sqlite3: true
> ```
>
> 同理，`strict-peer-dependencies` / `auto-install-peers` / `resolution-mode` 在 pnpm 11 中也不再从 `.npmrc` 读取，需写在 `pnpm-workspace.yaml`；`.npmrc` 只保留 `registry` 与鉴权设置。

- `build` / `type-check` / `test` 用 `pnpm -r`（**拓扑顺序**，utils → ui → web）。
- `dev` 用 `pnpm -r --parallel`（三个 watch 并行）。

## 3. TypeScript

- `tsconfig.base.json`：`extends: "@vue/tsconfig"`，`target: ES2022`、`module/moduleResolution: Bundler`、`strict: true`、`noUncheckedIndexedAccess: true`、`verbatimModuleSyntax: true`、`paths` 由各包自行声明。
- 主应用别名：`@/*` → `src/*`（Vite `resolve.alias` 与 tsconfig `paths` 双向同步）。
- 类型检查：`vue-tsc --noEmit`（不开启 `--build` 模式，避免子包产物耦合；如需增量再引入 project references）。

## 5. 样式规范（Stylelint 17）

### 5.2 配置

> **复核（2026-09-28，P8）**：间距组令牌强制（`/^(margin|padding|gap)/`）在 P3.5–P7 全流程中**仅触发过 1 次**真实报错（菜单页 `88px` 硬编码，改为令牌即修复），未出现「设计上确实需要非令牌值」的阻塞场景 → **维持现状，不收不松**（`docs/07` P8 任务 7 结论）。

```js
// stylelint.config.js
export default {
  extends: ['stylelint-config-standard-scss', 'stylelint-config-recommended-vue'],
  plugins: ['stylelint-scss', 'stylelint-declaration-strict-value'],
  overrides: [
    { files: ['**/*.{css,scss}'], customSyntax: 'postcss-scss' },
    { files: ['**/*.vue'], customSyntax: 'postcss-html' },
  ],
  rules: {
    // ---- L2：SCSS 约束 ----
    'scss/at-rule-no-unknown': true,
    'scss/dollar-variable-pattern': '^[_a-z][a-z0-9-]*$',
    'scss/dollar-variable-no-missing-interpolation': true,
    'scss/selector-no-redundant-nesting-selector': true,
    'max-nesting-depth': 4,
    'no-invalid-position-at-import-rule': [true, { ignoreAtRules: ['use', 'forward'] }],

    // ---- 设计令牌强制（error）：颜色 / 层级 / 字号 / 间距 ----
    'scale-unlimited/declaration-strict-value': [
      [
        // 颜色
        '/color$/',
        '/^background/',
        '/^border-.*color$/',
        'fill',
        'stroke',
        // 层级
        'z-index',
        // 字号与行高
        'font-size',
        'line-height',
        // 间距
        '/^(margin|padding|gap)/',
      ],
      {
        ignoreValues: [
          'transparent',
          'currentColor',
          'inherit',
          'initial',
          'unset',
          'none',
          'auto',
          '0',
          '1px',
          '50%',
          '100%',
        ],
        disableFix: true,
        severity: 'error',
      },
    ],
  },
}
```

> - 规则名 `scale-unlimited/declaration-strict-value` **只能声明一次**，因此所有受约束属性用正则收口到同一组。
> - 白名单中 `0 / auto / 50% / 100% / 1px` 是为间距与边框的常见写法放行。
> - **若落地后间距组阻塞严重，只需从属性数组移除 `'/(margin|padding|gap)/'`**（配置已按组收口，改一处生效）。
> - 该插件的 `disableFix: true`：值不合规时不自动改写（无法可靠推断应换成哪个令牌），交由人工修正。
> - **落地校验**：先跑 `pnpm lint:style --print-config` 确认所有规则名在 17.15.0 中有效；若 `max-nesting-depth` 已被移除，删除该项即可（嵌套约束非核心）。

### 5.5 与主题系统的关系（关键）

主题令牌见 `docs/04` §2。本节规则保证：

1. `--fsd-color-*` / `--el-color-*` 等令牌**只能经 `var()` 使用**；
2. 组件样式里不允许出现硬编码色值（`#409EFF` 之类）与硬编码 `z-index`；
3. 主题切换之所以能在运行时生效，前提就是「样式不写字面量」——这条规则是该前提的自动化保障。

## 8. 测试体系（Vitest 5）

- 配置位置：每个包各自 `vitest.config.ts`（`apps/web` 与 `packages/*` 分开），根用 `pnpm -r test` 汇总。
- 主应用配置要点：
  ```ts
  export default defineConfig({
    plugins: [vue()],
    test: {
      environment: 'happy-dom',
      globals: true,
      setupFiles: ['./vitest.setup.ts'],
      coverage: { provider: 'v8', reporter: ['text', 'html'], include: ['src/**/*.{ts,vue}'] },
    },
    resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } },
  })
  ```
- `vitest.setup.ts`：注册 Element Plus（或按需 stub）、全局指令、`@vue/test-utils` 配置、MSW server 生命周期；
  **i18n 也在此全局注册**（`config.global.plugins = [i18n]`）—— 各 spec **不要**再显式传 `plugins: [i18n]`：VTU 会与全局插件合并，Vue 会对同一实例打「Plugin has already been applied」警告（P8 实测）。
- **重型组件用 stub 提速**（P8 实测）：`AppLayout.spec` 原本渲染真实 Header（内含 LayoutSwitch/ThemeSwitch/LangSwitch 等 EP 下拉与选择器），5 个用例耗时 **34.8s**；
  改为 `stubs: { AppHeader: HeaderStub, FsdMenu: true, MenuTree: true }`（HeaderStub 用 `defineComponent` 注入 `LAYOUT_SHELL_KEY`，保留折叠按钮）后降到 **0.64s**（54×），
  布局分发与「壳层注入协议」仍被真实覆盖，视觉与联动细节交给浏览器 E2E（`docs/15` §2.6）。
- **服务端（`apps/server`）**：`vitest` + `supertest`，直接打 `createApp()` 不起端口；用内存库隔离（`DB_PATH=:memory:`）。
  配置与用例清单见 `docs/11` §8.5。
- 测试范围与优先级：
  1. `packages/utils`：`color`、`tree`、`storage` —— 必须覆盖（正确性影响主题与路由）
  2. 路由/权限纯函数：`filterRoutes`、`buildMenuTree`、`hasPermission`、`resolveMenuTitle`
  3. 关键组件：`AppLayout` 四种模式渲染、`MenuTree` 递归、`ThemeSwitch` 变量写入、`tabs.store` 的 LRU 与 `pruneInvalidViews`
     —— **进度（P8 完成 + P10 后补测）**：`tabs.store` 9 条（P6：去重/affix/关闭族/LRU/prune/持久化）；主题与语言 13+7 条（P5/P8）；
     `MenuTree`(4) / `AppTabs`(5) / `AppLayout`(7) 组件测试 P8 已补齐（含四模式分发、`meta.layout` 覆盖、页签关闭与右键菜单、小屏抽屉、水印/抽屉回归）；
     **P10 后补测批次**（web 145 → 191 用例）：页面注册表 `page-modules`、`menu-active` 纯函数（含 `canNavigate` 目录节点）、API 层（`menu.api` / `user.api`，mock axios 保留真实 `unwrap`）、面包屑 `AppBreadcrumb`（`matched` + i18n）、`LayoutSwitch` / `MenuIconPicker` / `ColorPickerPanel` / `error-handler`；
     web 覆盖率 44% → 61%（P8）→ 66.93%（P10 后补测：`entities/*/api` 与 `shared/lib` 达 100%）→ 68.81%（P11 主题扩展 +14 条）→ **84.99%**（P12：菜单配置页 4 个组件 +34 条，`features/menu-management/ui` 由 0% → **91.48%**）；
     **门槛（P12 起）**：`apps/web` 的 `lines/statements` 由 40 提到 **60**；`packages/utils` ≥ 90 不变；`apps/server` 不设门槛（决策 D6）
     P4/P6 阶段的浏览器端到端覆盖为四布局 33 项 + Tabs 16 项（`docs/15` §2.6 / §3.4）
  - **UI 测试踩坑（P10 补测）**：`FsdDialog` 内部的 EP `ElDialog` 是懒渲染 + teleport，`mount({ props: { visible: true } })` 拿不到面板内容 —— 测面板内部逻辑时把 `FsdDialog` 换成透传 slot 的替身（对话框行为归 `@repo/ui` 测）
  4. `packages/ui`：组件渲染 + 事件（快照不做硬性要求）
  5. `apps/server`：菜单 CRUD 与校验规则（用例清单见 `docs/11` §8.5）

## 11. CI（GitHub Actions）

```yaml
name: CI
on:
  push: { branches: [main] }
  pull_request: { branches: [main] }
concurrency: # 同分支/PR 的新推送取消旧运行（P13）
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
jobs:
  web: # 前端 + 子包（Node 矩阵：engines 下限 22 与主版本 24）
    name: web (node ${{ matrix.node }})
    runs-on: ubuntu-latest
    timeout-minutes: 25
    strategy:
      fail-fast: false
      matrix: { node: ['22.x', '24.x'] }
    steps:
      - uses: actions/checkout@v5
      - uses: pnpm/action-setup@v4
        with: { version: 11.9.0 }
      - uses: actions/setup-node@v5
        with: { node-version: ${{ matrix.node }}, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint # eslint + stylelint
      # 子包 dist 不入库：干净环境必须先构建，否则 web 的 type-check / test 解析不到 @repo/ui、@repo/utils
      - name: 构建子包（utils / ui）
        run: pnpm -r --filter "@repo/utils" --filter "@repo/ui" run build
      - run: pnpm type-check
      - run: pnpm test:cov # 阈值：utils ≥ 90 / web ≥ 60 / ui ≥ 40（P12 起）
      - run: pnpm build
      - name: 校验构建产物 # 仅主版本执行（P13）
        if: matrix.node == '24.x'
        run: pnpm verify:dist
      - name: 预览冒烟（静态可部署性）
        if: matrix.node == '24.x'
        run: pnpm smoke:preview

  server: # apps/server（决策 D6，不设覆盖率门槛）
    name: server
    runs-on: ubuntu-latest
    timeout-minutes: 15
    env: { DB_PATH: ':memory:' }
    steps:
      - uses: actions/checkout@v5
      - uses: pnpm/action-setup@v4
        with: { version: 11.9.0 }
      - uses: actions/setup-node@v5
        with: { node-version: '24.x', cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter @repo/server run type-check
      - run: pnpm --filter @repo/server run test # vitest + supertest（docs/11 §8.5）
```

- **矩阵与并发（P13）**：`web` job 覆盖 Node `22.x`（engines 下限）与 `24.x`（主版本）；`concurrency` 让同分支新推送取消旧运行；两 job 均有 `timeout-minutes` 兜底。
- **子包构建必须先于 `type-check` / `test`**：`packages/*/dist` 不入库，`apps/web` 的类型与运行时解析都走 `dist`（决策：产物消费）。首次真跑 CI 时 `web` job 在干净环境直接 `type-check` 失败（`TS2307: Cannot find module '@repo/ui'`），补「构建子包」步骤后通过。
- **产物校验（`pnpm verify:dist` → `scripts/verify-dist.mjs`）**：断言 utils/ui/web 三类产物存在且非空；`index.html` 引用的 `assets/*` 均真实存在；产物 CSS 含 `.el-icon`（P3 回归点）与 `--fsd-color-primary`（P11 回归点）；ui 产物保留 EP 按需样式导入；输出体积报告。
- **预览冒烟（`pnpm smoke:preview` → `scripts/preview-smoke.mjs`）**：`vite preview` 起静态服务（`PREVIEW_PORT`，默认 4173），断言 `/login` 200 且含 `#app`、`/dashboard` SPA 回退 200、`index.html` 引用的资源全部 200，结束自动关服务。
- **本地踩坑**：`vite preview` 默认绑 `localhost`（Windows 上即 IPv6 `::1`），脚本已显式 `--host 127.0.0.1` 后再用 `127.0.0.1` 探测；端口被占用时用 `PREVIEW_PORT=xxxx pnpm smoke:preview` 换端口。`verify:dist` 还会断言 `packages/ui` 的 `exports` 声明产物真实存在（防「产物改名、exports 没跟」）。
- 本地等价执行：`pnpm build && pnpm verify:dist && pnpm smoke:preview`；部署要求（SPA 回退 / 环境变量 / 同域反代）见 `README` §「构建与部署」。

> `server` job 上 `better-sqlite3` 若无匹配 prebuild 会触发源码编译；失败则给该 job 设 `DB_DRIVER=node-sqlite` 走 Node 内置驱动（详见 `docs/10` §1.10）。

## 13. oxlint 评估结论（2026-09-22）· 决策：暂缓引入

### 13.1 调研事实

| 项               | 现状                                                                                                                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 版本             | `oxlint` 1.85.0、`eslint-plugin-oxlint` 1.84.0、`@oxlint/migrate` 1.84.0、`oxlint-tsgolint` 7.0.2002、`vite-plugin-oxlint` 2.2.0、`oxfmt` 0.70.0                                                           |
| 与 Vite 8 的关系 | 同属 VoidZero / OXC 栈（Rolldown 用 OXC parser），但**当前无运行时集成、配置不共享**；`vite-plugin-oxlint` 只是 `cross-spawn` 起子进程把告警打到 Vite 终端，能力无增强（peer `vite >=5.0.0`，兼容 Vite 8） |
| Vue 支持         | 官方明确：`.vue` 仅 lint `<script>` 块，**模板不 lint**；`eslint-plugin-vue` 的模板规则须通过 **JS plugins（alpha）** 运行                                                                                 |
| Type-aware       | 59/61 条 typescript-eslint 类型感知规则，底层 `tsgo`，**要求 TypeScript 7.0+**；不支持 `baseUrl` 等旧 tsconfig 选项                                                                                        |
| 格式化           | `oxfmt` 仍为 0.70.0（0.x），不替代 Prettier 3.9.8                                                                                                                                                          |

### 13.2 决策

> **复核记录（2026-09-28，P8）**：§13.3 的 4 条触发条件**均未满足**（oxlint 仍不原生 lint Vue 模板；type-aware 仍要求 TS 7.x；`oxfmt` 未到 1.0；FSD 分层约束仍由 `no-restricted-imports` 承担）→ **维持 ESLint 单栈**，不引入 oxlint。

**维持 ESLint 10 单栈，oxlint 暂不引入。** 理由：

1. 本项目是**对外复用的模板**，lint 完整性优先于速度；而项目恰好命中 oxlint 两个短板——Vue 模板规则缺失、FSD 分层导入约束（现由 `no-restricted-imports` 承担）需自研 JS plugin。
2. 启用 type-aware 必须升到 TS 7.0.2，会连带推翻已定的 TS 6.0.3 决策，并让 `typescript-eslint` 失去支持，属于「牵一发动全身」。
3. JS plugins 仍为 alpha，把模板项目的质量门禁押在 alpha 能力上风险过高。

### 13.3 再评估触发条件（全部满足才重启评估）

1. oxlint 原生支持 **Vue 模板 lint**（不再依赖 alpha JS plugin），或 JS plugins 转为 stable；
2. oxlint type-aware **支持 TypeScript 6.x**，或团队已决定统一升级到 TS 7.x 且 `element-plus` 等生态验证通过；
3. `oxfmt` 达到 1.0（若同时考虑替换 Prettier）；
4. FSD 分层约束能用 oxlint 原生规则（`import` 插件）表达，或 JS plugin 稳定可用。

### 13.4 若未来切换的执行路径（备忘）

1. `pnpm add -D oxlint oxlint-tsgolint eslint-plugin-oxlint @oxlint/migrate`
2. `pnpm exec @oxlint/migrate` 由现有 flat config 生成 `.oxlintrc.json`
3. 先以**双跑**过渡：`oxlint` 跑非类型规则，ESLint 用 `eslint-plugin-oxlint` 关闭重叠规则（官方文档推荐的渐进迁移法）
4. Vue 模板与类型感知规则确认可替代后，再移除 `eslint-plugin-vue` / `typescript-eslint`
5. 同步更新 `docs/02` 版本表与本节结论（标注复核日期）
