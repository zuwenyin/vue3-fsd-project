## P10 · 服务端鉴权加固（决策 D5 复核：启用 403）

> 依据：决策 D5「本期不启用服务端权限校验」的复核时机为「接真后端前」；`docs/11` §5.9 的 403 说明在本阶段落地。
> 现状（P10 调研）：`authMiddleware` 已完成 Bearer token 校验（无 token → 401），但**不校验权限** —— editor 可直接调用菜单管理写接口。
> `TokenUser` 已携带 `roles` 与 `permissions`（seed：admin = `['*']`、editor = `['system:menu:view']`）。

**决策（P10 定稿）：按「权限点」校验，不按角色硬编码**

- 理由 ①：`permissions` 字段与登录载荷已就绪，admin 用 `*` 通配，editor 的权限点与前端 `v-permission="'system:menu:edit'"` **同源**（一处定义、两端一致）；
- 理由 ②：硬编码角色名会把「谁能改菜单」写死在路由层，后续加角色要改代码；权限点只需改种子数据。
- 规则：`permissions` 含 `*` 或含所需权限点之一 → 放行；否则 **403**（`ErrorCode.FORBIDDEN`）。

2. 挂载（`routes/menu.routes.ts`）：读 `GET /`、`GET /tree` → `system:menu:view`；写 `POST /`、`PUT /:id`、`DELETE /:id`、`POST /:id/move` → `system:menu:edit`
