### 3.1 `vite.config.ts`

```ts
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
  server: {
    port: 5173,
    proxy: {
      '/api': { target: 'http://localhost:3001', changeOrigin: true },
    },
  },
  build: {
    target: 'es2022',
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
          element: ['element-plus', '@element-plus/icons-vue'],
        },
      },
    },
  },
})
```

要点：

- 别名 `@` 与 `tsconfig.json` 的 `paths` 必须一致。
- **不引入**社区 Vite 插件（Vite 8 生态滞后，见 `docs/02` §8）。
- 构建分包先把 vue 生态与 EP 拆开，避免单包过大。

### 3.3 `src/shared/api/request.ts`

```ts
import axios, { AxiosError } from 'axios'
import { ElMessage } from 'element-plus'
import { storage } from '@repo/utils'
import type { ApiResponse } from './types'
import { env } from '@/shared/config/env'
import { TOKEN_KEY } from '@/shared/config/storage-keys'

export const request = axios.create({
  baseURL: env.apiBaseUrl,
  timeout: 10_000,
})

request.interceptors.request.use((config) => {
  const token = storage.get<string>(TOKEN_KEY)
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

request.interceptors.response.use(
  (res) => res,
  (error: AxiosError<ApiResponse<null>>) => {
    const code = error.response?.data?.code ?? error.response?.status
    const message = error.response?.data?.message ?? error.message
    if (code === 401) {
      // 清 token + 跳登录（P3 接入 auth store 后改为 store.logout()）
      storage.remove(TOKEN_KEY)
      location.href = '/login'
      return Promise.reject(error)
    }
    if (code === 403) ElMessage.error('无权限访问')
    else ElMessage.error(message || '请求失败')
    return Promise.reject(error)
  },
)
```

约定：

- **统一响应包装**：后端返回 `{ code, data, message }`，封装层再解一层 `data` 返回给调用方：
  ```ts
  export async function unwrap<T>(p: Promise<{ data: ApiResponse<T> }>): Promise<T> {
    const res = await p
    if (res.data.code !== 0) throw new Error(res.data.message)
    return res.data.data
  }
  ```
- 401 跳转逻辑在 P3 接入 `features/auth` 的 `logout()` 编排后改用它（内部依次清 `user.store`、清 storage token、跳登录，见 `docs/13` §3.6）；本阶段先用 `storage`。
- token 读写一律走 `@repo/utils` 的 `storage`：API 已定型为 `storage.get/set/remove/clear`，键统一 `fsd:` 前缀（决策 D1，签名见 `docs/10` §2.1）；`docs/01` §7 禁止直接用 `localStorage`。
- 键名集中管理（`shared/config/storage-keys.ts`，决策 D1）：`TOKEN_KEY = 'fsd:token'`、`THEME_KEY = 'fsd:theme'`、`LAYOUT_KEY = 'fsd:layout'`、`TABS_KEY = 'fsd:tabs'`；禁止散落字符串字面量。
- `ElMessage` 显式 import（`import { ElMessage } from 'element-plus'`）；该文件位于 `shared/`，只允许引入 EP 的**非组件 API**（Message 为函数调用，不违反「组件从 `@repo/ui` 出」的约定）。

```ts

export const pinia = createPinia()
export function setupPinia(app: App) {
  app.use(pinia)
}

// providers/element.ts（倾向 ElConfigProvider + 局部引入，不叠加 app.use(ElementPlus)）
export function setupElement(app: App) {

// providers/mock.ts（P2 仅为占位，真实 handlers 见 docs/06 §9）
export async function setupMock() {
  if (!env.useMock) return
  const { worker } = await import('./mocks/browser')
  await worker.start({ onUnhandledRequest: 'bypass' })
}

// shared/lib/directives/index.ts（P2 空实现，P3 注册 v-permission）
export function registerDirectives(_app: App) {
  /* P3: app.directive('permission', permission) */
}
```

### 本轮新增的两项约定

- **CSS 类名采用 BEM**（`block` / `block__element` / `block--modifier`，小写 kebab）：`stylelint.config.js` 已配 `selector-class-pattern` 放行 BEM（`config-standard` 默认只认 kebab-case，会误报 `fsd-table__pagination`）。`docs/01` 命名规范同步补充。
- **构建清空 `dist` 受本机 shim 影响**：IDE 注入的 `node-safe-delete-shim` 会接管 `fs.rmSync`，导致 `@repo/ui` 构建在 `emptyDir` 阶段报 `[safe-delete] 操作失败`；清掉 `NODE_OPTIONS` / `CODEBUDDY_SAFE_DELETE_ENABLED=0` 后 `pnpm build` 退出码 0。非项目配置问题，CI 与纯终端不受影响。

### 补记：Element Plus 样式遗漏（P3 阶段修复）

P2 的两个「接口层」验收项（`/login` 返回 200、代理登录成功）**无法发现视觉问题**：`@repo/ui` 各组件只 `import` 了 EP 组件、从未 `import` 其样式，导致首屏渲染时：

- 图标（`FsdIcon` / `el-icon`）因缺少 `svg{width:1em}` 规则被撑成数百 px；
- 输入框、按钮、菜单均为浏览器默认样式（`fsd-button` 变白底黑字、`el-message` 无样式）。

修复（P3 阶段，`docs/05` §Element Plus 引入规则已补规则）：

1. `@repo/ui` 15 个组件补 `import 'element-plus/es/components/<name>/style/css'`；
2. `FsdIcon` 补 `class="el-icon"`（尺寸规则来自 `base.css`）；
3. 主应用 `app/providers/element.ts` 补 `message` 样式（`ElMessage` 由主应用直接使用）；
4. 单测侧新增根目录插件 `vitest.element-plus-style-stub.ts`，把 EP 样式入口替换为空模块（否则 Node 报 `Unknown file extension ".css"`；`server.deps.inline: ['element-plus']` 会让 ui 测试从 ~10s 涨到 ~53s）。

浏览器复验：登录页表单/按钮/密码眼睛图标正常，侧边栏图标 14×14（`PASSWORD_ICON_BOX` 实测），生产产物 `dist/assets/dist-*.css` 119.8KB 含 EP 按需规则。

## 6. 风险与回退

| 风险                              | 现象                          | 回退                                                                                              |
| --------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------- |
| 服务端未启动导致登录 500          | Network 报错                  | 先用 `VITE_USE_MOCK=true` 临时走 MSW handlers（`docs/06` §9），联调前切回                         |
| Element Plus 全局 vs 按需冲突     | 样式双份、体积大              | 统一：`@repo/ui` 内显式 import 组件；主应用只做 `ElConfigProvider` 与 `app.use`（二选一，不叠加） |
| `element-plus/global` 类型缺失    | 模板里 `ElMessage` 报错       | 从 `types` 中移除，改为显式 import                                                                |
| Vite 8 对 `manualChunks` 行为变化 | 构建告警                      | 移除 `manualChunks`，交给默认分包                                                                 |
| 别名不一致                        | `type-check` 报找不到 `@/...` | `vite.config.ts` 与 `tsconfig.json` 双写且保持一致                                                |
