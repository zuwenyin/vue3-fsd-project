# 13 · 实施文档 · P3 动态路由与权限

> 对应 `docs/07` 的 **P3**。契约以 `docs/03` §1 为准，数据来源为 `docs/11` 的 Express 服务（`/api/user/routes`）。
> 本阶段额外提供「**路由热替换**」能力（`applyRoutes()` / `clearDynamicRoutes()`），供 `docs/14` 菜单配置页复用。

## 0. 目标与范围

- 登录后由后端下发路由树 → 映射组件 → `addRoute` 到 `Layout` 下 → 生成菜单树；
- 路由级过滤（`roles` / `permissions`）、按钮级指令 `v-permission`；
- 登出/切换账号清理动态路由；
- 提供可被配置页调用的 **重新应用路由** 函数。

## 3. 核心实现

### 3.1 `app/router/dynamic.ts`

```ts
import type { Component } from 'vue'
import type { RouteRecordRaw } from 'vue-router'
import type { BackendRouteNode } from '@/entities/menu'
import { resolvePageComponent } from '@/shared/lib/page-modules'
import { LAYOUT_ROUTE_NAME } from './constant-routes'

// ★ import.meta.glob 与白名单位于 shared/lib/page-modules.ts（docs/03 §3），
//   原因：菜单配置页（features）也要用白名单，放 app/ 会形成向上依赖。

/** 已注册的动态路由名，用于精确移除（热替换的关键） */
const dynamicRouteNames = new Set<string>()

function toRouteRecord(node: BackendRouteNode, parentPath = ''): RouteRecordRaw | null {
  const { children, component, meta, ...rest } = node
  const comp = resolvePageComponent(component)
  if (component && !comp) return null // 组件解析失败：整节点丢弃（由调用方兜底 404）
  const record: RouteRecordRaw = {
    ...rest,
    component: comp as Component,
    meta: { ...meta },
  }
  if (children?.length) {
    record.children = children
      .map((c) => toRouteRecord(c, node.path))
      .filter((r): r is RouteRecordRaw => r !== null)
  }
  return record
}

export function registerDynamicRoutes(nodes: BackendRouteNode[], router: Router) {
  for (const node of nodes) {
    const record = toRouteRecord(node)
    if (!record) continue
    const name = String(record.name)
    // 同名路由先移除再注册，保证「定义变更」（改 path / component / meta）能生效
    if (router.hasRoute(name)) router.removeRoute(name)
    router.addRoute(LAYOUT_ROUTE_NAME, record)
    dynamicRouteNames.add(name)
  }
}

/** 移除在新路由表中已消失的旧路由（用于热替换的清理阶段） */
export function removeStaleRoutes(router: Router, keep: Set<string>) {
  for (const name of [...dynamicRouteNames]) {
    if (keep.has(name)) continue
    if (router.hasRoute(name)) router.removeRoute(name)
    dynamicRouteNames.delete(name)
  }
}

export function clearDynamicRoutes(router: Router) {
  dynamicRouteNames.forEach((name) => router.hasRoute(name) && router.removeRoute(name))
  dynamicRouteNames.clear()
}

/** 重新拉取并应用路由（菜单配置页的「应用变更」复用，见 docs/14 §5.2） */
export async function applyRoutes(router: Router): Promise<MenuItem[]> {
  const nodes = await fetchUserRoutes()
  const auth = useUserStore()
  const accessible = filterRoutes(nodes, auth.permissions, auth.roles)
  // ★ 顺序：先注册新的（同名覆盖），再清理消失的 —— 当前所在路由全程有效，不会瞬间落 404
  registerDynamicRoutes(accessible, router)
  const nextNames = new Set(collectNames(accessible))
  removeStaleRoutes(router, nextNames)
  const tree = buildMenuTree(accessible)
  useMenuStore().setTree(tree)
  return tree
}
```

要点：

- `import.meta.glob` 的 key 用**绝对路径** `/src/pages/**/*.vue`（编译期确定，不依赖 alias）。
- 生产环境解析失败 → 调用方兜底到 `NotFound`；开发环境 `console.error` 明确提示。
- `dynamicRouteNames` 是热替换的基础。**顺序已定**：先 `registerDynamicRoutes`（同名先 `removeRoute` 再 `addRoute`，保证定义变更生效）→ 再 `removeStaleRoutes`（清理新表中已消失的）。这样当前所在路由在整个过程中**始终有效**，不会瞬间落 404（`docs/14` §5.2 时序图同此顺序）。
- 404 顺序（`docs/03` §2 注意事项）：动态路由挂到 `Layout` 下，404 作为**顶层通配**已存在，不会被覆盖；注册后无需重排。

### 3.2 `entities/permission/lib/filter-routes.ts`

```ts
export function filterRoutes(
  nodes: BackendRouteNode[],
  permissions: string[],
  roles: string[],
): BackendRouteNode[] {
  return nodes
    .filter((node) => hasPermission(node.meta?.permissions, permissions, roles))
    .map((node) => {
      const children = node.children ? filterRoutes(node.children, permissions, roles) : undefined
      return { ...node, children: children?.length ? children : undefined }
    })
    .filter((node) => node.children?.length || node.component || node.path)
}
```

- 语义：**命中 `meta.roles` 或 `meta.permissions` 其一即可通过**；未配置则放行（`docs/03` §6）。
- `admin` 角色直通（见 `hasPermission`）。
- 过滤掉「既无子节点也无组件」的空目录节点。

### 3.3 `entities/permission/lib/has-permission.ts`

```ts
export function hasPermission(
  need?: string | string[],
  owned: string[] = [],
  roles: string[] = [],
): boolean {
  if (!need || (Array.isArray(need) && need.length === 0)) return true
  if (roles.includes('admin')) return true
  if (Array.isArray(need)) {
    const perms = need.filter((p) => !p.startsWith('role:'))
    const needRoles = need.filter((p) => p.startsWith('role:')).map((p) => p.slice(5))
    if (needRoles.length && needRoles.some((r) => roles.includes(r))) return true
    return perms.length === 0 ? false : perms.some((p) => owned.includes(p))
  }
  return need.startsWith('role:') ? roles.includes(need.slice(5)) : owned.includes(need)
}
```

> 相对 `docs/03` §6 的增强：支持 `role:xxx` 前缀与 `meta.roles` 的统一判定，其余语义不变。

### 3.4 `entities/menu/lib/build-tree.ts`

export function buildMenuTree(routes: BackendRouteNode[]): MenuItem[]

规则（`docs/03` §5）：

1. `hideInMenu` 移除；
2. `hideChildrenInMenu` 时把子节点提升到当前层；

5. `key` = `route.name`，`path` 为可跳转路径（子级拼接父级 path）。

### 3.4.1 菜单标题回落（`entities/menu/lib/resolve-title.ts`）

> 决策 D2：**本期不接 vue-i18n**，`titleKey` 仅作为字段保留；`resolveMenuTitle()` 先做回落，P7 接入 i18n 后只需替换其内部实现。

```ts
export interface TitleSource {
  title?: string
  titleKey?: string
}

/** titleKey 优先；本期无 i18n 时回落 title，再回落空串 */
export function resolveMenuTitle(node: TitleSource, t?: (key: string) => string): string {
  if (node.titleKey && t) return t(node.titleKey)
  return node.title ?? ''
}
```

约束：

- 所有菜单渲染位置（侧边栏 `MenuTree`、面包屑、Tabs 页签）**必须**经 `resolveMenuTitle()`，禁止直接读 `meta.title`。
- `t` 参数本期不传（不引 i18n 依赖）；P7 传入 `vue-i18n` 的 `t` 即可，调用方无需改动。
- 单测：`titleKey` 有值且有 `t` → 用 `t` 的结果；无 `t` → 回落 `title`；两者皆空 → `''`。

### 3.5 `app/router/guard.ts`

```ts
let routesLoaded = false

router.beforeEach(async (to) => {
  const auth = useUserStore()
  if (to.meta.public) return true
  if (!auth.token) return { name: 'Login', query: { redirect: to.fullPath } }

  if (!routesLoaded) {
    try {
      await applyRoutes(router) // 拉取 → 过滤 → 注册 → 菜单树
      routesLoaded = true
      return { ...to, replace: true } // 重新进入，确保匹配到新路由
    } catch {
      auth.logout()
      return { name: 'Login' }
    }
  }
  return true
})

export function resetRoutesLoaded() {
  routesLoaded = false
}
```

- 标题、Tabs 记录在 P6/P7 接入（本阶段只做权限与注册）。
- `applyRoutes` 与守卫共用同一函数，保证「首次加载」与「配置页应用变更」行为一致。

### 3.6 登出清理

```ts
async function logout() {
  clearDynamicRoutes(router) // ① 精确移除动态路由
  useMenuStore().clear() // ② 清空菜单树
  resetRoutesLoaded() // ③ 复位守卫标记
  storage.remove(TOKEN_KEY) // ④ 清 token（storage，见 D1；不走裸 localStorage）
  useUserStore().$reset() // ⑤ 清空 roles / permissions / profile
  useTabsStore().reset() // ⑥ P6 接入：清空页签与 keep-alive 缓存
  router.replace({ name: 'Login' })
}
```

> 不采用「重建 router 实例」：热替换方案更轻量，且不丢当前页面状态（`docs/03` §4 二者择一，本方案选前者，决策 D10）。
> 顺序不可变：先清路由，再清 store，最后跳登录——否则守卫可能在跳转途中读到已清空的 token 而反复重定向。

### 3.7 `v-permission`（`shared/lib/directives/permission.ts`）

```ts
type PermissionValue = string | string[]

export const permission: ObjectDirective<HTMLElement, PermissionValue> = {
  mounted(el, binding) {
    if (!check(binding.value)) hide(el)
  },
  // 权限变化（换账号 / 重新拉用户信息）后重新判定，避免残留隐藏态
  updated(el, binding) {
    check(binding.value) ? show(el) : hide(el)
  },
}

function check(value?: PermissionValue) {
  const { permissions, roles } = useUserStore()
  return hasPermission(value, permissions, roles)
}

/** 用占位注释节点替换真实节点，保证 show() 能恢复（直接 remove() 不可逆） */
const placeholder = new WeakMap<HTMLElement, Comment>()
function hide(el: HTMLElement) {
  if (placeholder.has(el)) return
  const comment = document.createComment('v-permission')
  el.parentNode?.replaceChild(comment, el)
  placeholder.set(el, comment)
}
function show(el: HTMLElement) {
  const comment = placeholder.get(el)
  if (!comment) return
  comment.parentNode?.replaceChild(el, comment)
  placeholder.delete(el)
}
```

在 `app/index.ts` 中 `app.directive('permission', permission)`（P2 已留 `registerDirectives` 空实现，见 `docs/12` §3.6）。

用法：`v-permission="'system:user:add'"`、`v-permission="['system:menu:edit', 'role:admin']"`。

## 7. 风险与回退

| 风险                                  | 现象             | 回退                                                                                                                   |
| ------------------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `addRoute` 后首次进入匹配不到         | 白屏或落 404     | 守卫中必须 `return { ...to, replace: true }` 重新进入                                                                  |
| 热替换瞬间当前路由消失                | 应用变更后闪 404 | 采用「先注册后清理」（§3.1）；禁止先 `clearDynamicRoutes` 再注册                                                       |
| 路由名冲突                            | 注册静默失败     | `registerDynamicRoutes` 中 `hasRoute` 预检 + 警告日志                                                                  |
| `import.meta.glob` 在 vitest 中不可用 | 单测报 key 为空  | 单测只测纯函数（`filterRoutes` / `buildMenuTree`），不测 `dynamic.ts`；或给 glob 加 `{ eager: false }` 并在测试中 mock |
| keep-alive 缓存名与路由名不一致       | 缓存失效         | 统一以 `route.name` 为 key（`docs/15` §3）                                                                             |
| 注销后 `routesLoaded` 未复位          | 换账号沿用旧路由 | 必须调用 `resetRoutesLoaded()`                                                                                         |
