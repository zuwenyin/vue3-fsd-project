# 14 · 实施文档 · P3.5 菜单 / 路由配置页

> 对应 `docs/07` 的 **P3.5**。数据来自 `docs/11` 的 Express + SQLite 服务；路由热替换复用 `docs/13` 的 `applyRoutes()`。
> UI 形态（已确认）：**左右分栏**（左：树形表格 + 行拖拽排序；右：选中项表单直编）+ **新增走 Dialog** + **组件路径下拉**。

## 0. 目标与范围

- 在后台里可视化维护菜单/路由：增删改、拖拽排序与换父级、隐藏/缓存/权限配置；
- 保存后点「**应用变更**」，侧边栏与路由表**即时刷新**（不刷新页面）；
- 配置页自身也是一条菜单记录（`system/menu/index`），受同一套权限与路由机制约束。

## 1. 前置依赖

- P3 完成（`docs/13`）：`applyRoutes()` / `clearDynamicRoutes()` 可用
- `apps/server` 菜单 CRUD 与 move 接口可用（`docs/11` §5.5~5.8）
- 依赖：`vue-draggable-plus 0.6.1` + `sortablejs 1.15.7` + `@types/sortablejs 1.15.9`（`docs/02` §5.5）

### 4.1 左栏 · `MenuTreeTable.vue`

```vue
<FsdTable
  :data="tree"
  row-key="id"
  default-expand-all
  :tree-props="{ children: 'children' }"
  :loading="loading"
  highlight-current-row
  @current-change="onSelect"
>
  <template #drag><span class="drag-handle">⠿</span></template>
  <template #title="{ row }"><FsdIcon :name="row.icon" /> {{ row.title }}</template>
  <template #status="{ row }"><FsdTag :type="row.status ? 'success' : 'info'">{{ row.status ? '启用' : '停用' }}</FsdTag></template>
  <template #actions="{ row }"><!-- 新增子级 / 编辑 / 删除 --></template>
</FsdTable>
```

- `columns` 定义：拖拽（44）/ 菜单标题（180，`#title` 插槽）/ 路由地址（`path`，140）/ 组件路径（`component`，180）/ 排序（`orderNo`，80）/ 状态（80，`#status` 插槽）/ 操作（180，fixed right，`#actions` 插槽）。
- `row-key="id"` + `tree-props` 才能正确渲染层级与半选展开。
- **行选中**：`highlight-current-row`（`FsdTable` 必须把它透传给 el-table）+ 编排层**同时监听 `row-click` 兜底**——只挂 `@current-change` 时点击行不会写 `currentRow`，右侧表单不会加载（见 §11 缺陷 ③）；`select(id)` 对同 id 幂等。
- 删除按钮：有子节点时 `disabled` + `tooltip` 提示「请先删除子菜单」。
- 工具栏：`新增根菜单`（打开 `FsdDialog`，parentId=null）、`展开/折叠全部`（切换 `default-expand-all` 或遍历 `toggleRowExpansion`）。

### 4.2 右栏 · `MenuDetailForm.vue`

- 选中行即加载（`watch(selectedId)` → 深拷贝进 `form`），**未保存的修改**用 `isFormDirty` 标记，切换行时提示。
- 字段分组用 `FsdForm` + `FsdFormItem`，分四个分区（基础 / 路由 / 显示 / 权限）。
- 底部固定操作条：`删除`（danger 描边）、`取消`（还原）、`保存`（primary）。
- 校验规则（`menu-form.ts`）：
  - `name`：`/^[A-Z][A-Za-z0-9]*$/`（必须大写开头，作为路由名），必填
  - `path`：非外链时必填，禁止空格
  - `component`：`componentOptions` 下拉可选，也允许手填（手填时给出「未匹配到页面组件」的 warning 提示，不阻断保存）
  - `title`：必填，≤ 20 字
  - `orderNo`：`0–99999` 整数

### 4.3 新增 Dialog · `MenuEditDialog.vue`

- 字段：`上级菜单`（`FsdTreeSelect`，默认带入当前选中行）、`菜单类型`（目录 / 菜单 / 外链）、以及按类型显隐的其余字段。
- 「目录」：`component` 置空、"仅分组"提示；「外链」：`path` 必须为 `http(s)://` 开头；「菜单」：显示完整字段。
- 提交：`POST /api/menus` → 成功后局部刷新树 + 选中新节点 + `hasDirty = true`。

```ts
  const form = ref<MenuFormModel | null>(null)
  const loading = ref(false)

  const hasDirty = computed(() => useMenuStore().hasDirty)

  async function load() {
    tree.value = await menuApi.tree()
  }
  function select(id: number) {
    /* 加载详情 → 填充 form */
  }

  async function save() {
    await menuApi.update(selectedId.value!, form.value!)
    useMenuStore().markDirty()
    await refreshNode() // 只刷新受影响节点，不整表重载
  }

    await ElMessageBox.confirm('确认删除该菜单？', '删除确认', { type: 'warning' })
    await menuApi.remove(id)
    useMenuStore().markDirty()
    await load() // 删除涉及子节点，整树重载更简单可靠
  }

  async function move(payload: MoveMenuPayload) {
    const snapshot = cloneDeep(tree.value) // 乐观更新快照
    applyLocalMove(tree.value, payload)
    try {
      await menuApi.move(payload)
      useMenuStore().markDirty()
    } catch (e) {
      tree.value = snapshot
      ElMessage.error(messageOf(e))
    }
  }

  async function applyChanges() {
    /* 见 §5.2 */
  }
  async function reset() {
    await load()
    useMenuStore().clearDirty()
  }

  return {
    tree,
    selectedId,
    form,
    loading,
    hasDirty,
    load,
    select,
    save,
    remove,
    move,
    applyChanges,
    reset,
  }
}
```

要点：

- 拖拽/保存用**乐观更新 + 失败回滚**，回滚靠 `cloneDeep` 快照。
- 错误提示统一取后端 `message`（`shared/api` 的 `unwrap` 抛出的 `Error.message`）。
- `hasDirty` 驱动顶部提示条；「应用变更」成功后清零。

### 5.2 热更新时序

```mermaid
flowchart TD
  A[编辑 / 拖拽 / 增删] --> B[调用后端 CRUD 写库成功]
  B --> C[点击 应用变更]
  C --> D[GET /api/user/routes]
  D --> E[filterRoutes 按 roles / permissions 过滤]
  E --> F[resolvePageComponent 映射 + 注册新路由（同名先 remove 再 add）]
  F --> G[removeStaleRoutes 清理已消失的旧路由]
  G --> H[menuStore.setTree buildMenuTree]
  H --> I{当前路由是否仍存在}
  I -->|否| J[router.replace('/dashboard') + ElMessage.warning]
  I -->|是| K[保持当前页, 侧边栏即时更新]
```

```ts
// features/menu-management/model/use-menu-management.ts
async function applyChanges() {
  loading.value = true
  try {
    await applyRoutes(router) // docs/13 §3.1
    const current = String(router.currentRoute.value.name ?? '')
    if (current && current !== 'Layout' && !router.hasRoute(current)) {
      await router.replace('/dashboard')
      ElMessage.warning('当前页面已被移除，已返回仪表盘')
    } else {
      ElMessage.success('菜单已更新')
    }
    tabsStore.pruneInvalidViews(router) // P6：清理失效页签与缓存（docs/15 §3）
    useMenuStore().clearDirty()
  } finally {
    loading.value = false
  }
}
```

注意事项：

- **热替换顺序已定**（`docs/13` §3.1）：先注册新路由（同名先 `removeRoute` 再 `addRoute`）→ 再 `removeStaleRoutes()` 清理消失的。当前路由全程有效，不会瞬间落 404；因此 `hasRoute` 判定只用于「该路由确实被删掉」时再跳转，而不是为了避免闪断。
- `keep-alive` 的 `:include` 依赖 `tabs.cachedViews`，被删除菜单对应的缓存需由 `pruneInvalidViews(router)` 剔除。**P3.5 未调用**（此时还没有 `tabsStore`）：`app/router/menu-apply.ts` 只做「拉路由 + 热替换 + 失效跳转」，接入点留在 `applyMenuChanges()` 成功分支之后，由 P6 实现（`docs/15` §3.2）。
- **「应用变更」的语义（决策 D4）**：本期**保存即写库并生效**，按钮只做「重新拉路由表 + 热替换」，**不调用任何发布接口**；生产环境才会出现「保存 → 发布」两步与「有未发布变更」提示（后端已预留 `publish_status` / `published_at`，见 `docs/11` §5.10）。
- 按钮文案保持「应用变更」，`hasDirty` 提示条文案：「有未应用的菜单变更，应用后即时生效」。
- **能力注入方式（决策 D15）**：`applyRoutes()` / `router` 都在 `app/router/*`，而 §3 禁止 features 导入 `app/*`；因此 `applyMenuChanges()` 留在 app 层，经 **app 级 `provide`**（`provideMenuHotApply(app)`，`app/index.ts` 装配）下放，feature 侧只 `inject(MENU_HOT_APPLY_KEY)`。**统一走 app 级 provide**：组件级 `provide` 在本项目单测环境实测拿不到值（见 §11）。

### 5.3 拖拽排序（`MenuTreeTable.vue`）

```ts
import { nextTick, onMounted, ref, shallowRef, watch } from 'vue'
import { useDraggable } from 'vue-draggable-plus'

/** FsdTable 经 defineExpose 暴露的能力（泛型 SFC 无法用 InstanceType，按结构声明） */
const tableRef = ref<{ bodyRef: HTMLElement | null; refreshSortable: () => void } | null>(null)
const tbodyRef = shallowRef<HTMLElement | null>(null)

const draggable = useDraggable(tbodyRef, {
  immediate: false, // 元素在挂载后才由 FsdTable 暴露，统一交给 syncSortable() 初始化
  handle: '.menu-tree-table__drag-handle',
  animation: 160,
  ghostClass: 'menu-row-ghost',
  onMove: (evt) => /* 禁止拖到自身子孙 + 深度预判（决策 D3） */,
  onEnd: (evt) => {
    // ★ 关键：先在「拖拽后的 DOM 顺序」上采集行序，再还原 DOM；反过来会拿到旧顺序
    const list = collectRows(tbodyRef.value!)
    restoreDom(evt)
    const payload = toMovePayload(list, dragIndex, heightOf(draggedId))
    if (payload) emit('move', payload)
    else ElMessage.warning('目标层级非法（最多 3 级）')
  },
})

function syncSortable() {
  tableRef.value?.refreshSortable() // 先重新抓 bodyRef
  const tbody = tableRef.value?.bodyRef
  if (!tbody) return
  tbodyRef.value = tbody
  draggable.start(tbody) // 库只在初始化时解析元素，元素变化后必须显式重绑
}

onMounted(() => void nextTick(syncSortable))
watch(
  () => props.tree,
  () => void nextTick(syncSortable),
) // 树数据变化后重新绑定
```

- **绑定目标**：优先用 `FsdTable` 暴露的 `bodyRef`（`tbody` 元素），**不要**用 `.el-table__body-wrapper tbody` 选择器硬编码——那是 `el-table` 的内部结构，升级易失效。
- 绑定时机：`useDraggable` 传 `immediate: false`，由 `syncSortable()` 在 `onMounted` + `nextTick`、以及 `tree` 变化后执行 `refreshSortable()` + `start(tbody)` 重绑。
- **落点采集时机**：`collectRows()` 必须在 `restoreDom()` **之前**调用（见 §11 缺陷 ②），否则读到的是还原后的旧行序，落点全丢。
- 拖拽结束后**不直接改 DOM 结果**，而是发 `move` 事件交由编排层乐观更新 + 调后端，保证前后端一致。
- 后端 `order_no` 用**中间数插入**（`docs/11` §5.8），前端无需关心数值。
- `< 960px` 降级为「上移 / 下移」按钮（不绑定 sortable），见 §4.7。

### 5.4 层级上限校验（决策 D3 · `MAX_DEPTH = 3`）

双端一致，后端为准：

| 端                   | 行为                                                                                                                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 后端（`docs/11` §6） | 创建 / 移动时计算目标深度，`> 3` 直接 `422` 拒绝（常量 `MAX_DEPTH`）                                                                                                                                     |
| 前端                 | ① 3 级节点上「新增子级」按钮 `disabled` + `tooltip` 提示「最多 3 级」；② 拖拽 `onMove` 中预判目标深度，超限返回 `false`（显示禁止态）；③ 若仍收到后端 `422`，`ElMessage.error` 展示后端 `message` 并回滚 |

```ts

export const MENU_MAX_DEPTH = 3 // 与后端 MAX_DEPTH 保持一致（常量名不同，值必须相同）

export function depthOf(tree: MenuTreeNode[], id: number): number {
  /* 递归求深度 */
}

}
```
