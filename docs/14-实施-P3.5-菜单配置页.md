# 14 · 实施文档 · P3.5 菜单 / 路由配置页

> 对应 `docs/07` 的 **P3.5**。数据来自 `docs/11` 的 Express + SQLite 服务；路由热替换复用 `docs/13` 的 `applyRoutes()`。
> UI 形态（已确认）：**左右分栏**（左：树形表格 + 行拖拽排序；右：选中项表单直编）+ **新增走 Dialog** + **组件路径下拉**。

## 0. 目标与范围

- 在后台里可视化维护菜单/路由：增删改、拖拽排序与换父级、隐藏/缓存/权限配置；
- 保存后点「**应用变更**」，侧边栏与路由表**即时刷新**（不刷新页面）；
- 配置页自身也是一条菜单记录（`system/menu/index`），受同一套权限与路由机制约束。

## 1. 前置依赖

- P3 完成（`docs/13`）：`applyRoutes()` / `clearDynamicRoutes()` 可用
- `apps/server` 菜单 CRUD 与 move 接口可用（`docs/11` §5.5~5.8）
- 依赖：`vue-draggable-plus 0.6.1` + `sortablejs 1.15.7`（`docs/02` §5.5）

### 4.2 右栏 · `MenuDetailForm.vue`

- 选中行即加载（`watch(selectedId)` → 深拷贝进 `form`），**未保存的修改**用 `isFormDirty` 标记，切换行时提示。
- 字段分组用 `FsdForm` + `FsdFormItem`，分四个分区（基础 / 路由 / 显示 / 权限）。
- 底部固定操作条：`删除`（danger 描边）、`取消`（还原）、`保存`（primary）。
- 校验规则（`menu-form.ts`）：
  - `name`：`/^[A-Z][A-Za-z0-9]*$/`（必须大写开头，作为路由名），必填
  - `path`：非外链时必填，禁止空格

  - `title`：必填，≤ 20 字
  - `orderNo`：`0–99999` 整数

### 4.3 新增 Dialog · `MenuEditDialog.vue`

- 字段：`上级菜单`（`FsdTreeSelect`，默认带入当前选中行）、`菜单类型`（目录 / 菜单 / 外链）、以及按类型显隐的其余字段。

### 5.1 编排（`model/use-menu-management.ts`）

```ts
export function useMenuManagement() {
  const tree = ref<MenuTreeNode[]>([])
  const selectedId = ref<number | null>(null)
  const form = ref<MenuFormModel | null>(null)
  const loading = ref(false)
  // 决策：hasDirty 唯一归属 menuStore，此处只做只读计算属性（避免两处状态不同步）
  const hasDirty = computed(() => useMenuStore().hasDirty)

  async function load() {
    tree.value = await menuApi.tree()
  }
  function select(id: number) {
    /* 加载详情 → 填充 form */
  }

  async function save() {
    await menuApi.update(selectedId.value!, form.value!)
    useMenuStore().markDirty()
    await refreshNode() // 只刷新受影响节点，不整表重载
  }

  async function remove(id: number) {
    await ElMessageBox.confirm('确认删除该菜单？', '删除确认', { type: 'warning' })
    await menuApi.remove(id)
    useMenuStore().markDirty()
    await load() // 删除涉及子节点，整树重载更简单可靠
  }

  async function move(payload: MoveMenuPayload) {
    const snapshot = cloneDeep(tree.value) // 乐观更新快照
    applyLocalMove(tree.value, payload)
    try {
      await menuApi.move(payload)
      useMenuStore().markDirty()
    } catch (e) {
      tree.value = snapshot
      ElMessage.error(messageOf(e))
    }
  }

  async function applyChanges() {
    /* 见 §5.2 */
  }
  async function reset() {
    await load()
    useMenuStore().clearDirty()
  }

  return {
    tree,
    selectedId,
    form,
    loading,
    hasDirty,
    load,
    select,
    save,
    remove,
    move,
    applyChanges,
    reset,
  }
}
```

要点：

- 拖拽/保存用**乐观更新 + 失败回滚**，回滚靠 `cloneDeep` 快照。
- 错误提示统一取后端 `message`（`shared/api` 的 `unwrap` 抛出的 `Error.message`）。
- `hasDirty` 驱动顶部提示条；「应用变更」成功后清零。

### 5.2 热更新时序

```mermaid
flowchart TD
  A[编辑 / 拖拽 / 增删] --> B[调用后端 CRUD 写库成功]
  B --> C[点击 应用变更]
  C --> D[GET /api/user/routes]
  D --> E[filterRoutes 按 roles / permissions 过滤]
  E --> F[resolvePageComponent 映射 + 注册新路由（同名先 remove 再 add）]
  F --> G[removeStaleRoutes 清理已消失的旧路由]
  G --> H[menuStore.setTree buildMenuTree]
  H --> I{当前路由是否仍存在}
  I -->|否| J[router.replace('/dashboard') + ElMessage.warning]
  I -->|是| K[保持当前页, 侧边栏即时更新]
```

```ts
// features/menu-management/model/use-menu-management.ts
async function applyChanges() {
  loading.value = true
  try {
    await applyRoutes(router) // docs/13 §3.1
    const current = String(router.currentRoute.value.name ?? '')
    if (current && current !== 'Layout' && !router.hasRoute(current)) {
      await router.replace('/dashboard')
      ElMessage.warning('当前页面已被移除，已返回仪表盘')
    } else {
      ElMessage.success('菜单已更新')
    }
    tabsStore.pruneInvalidViews(router) // P6：清理失效页签与缓存（docs/15 §3）
    useMenuStore().clearDirty()
  } finally {
    loading.value = false
  }
}
```

注意事项：

- **热替换顺序已定**（`docs/13` §3.1）：先注册新路由（同名先 `removeRoute` 再 `addRoute`）→ 再 `removeStaleRoutes()` 清理消失的。当前路由全程有效，不会瞬间落 404；因此 `hasRoute` 判定只用于「该路由确实被删掉」时再跳转，而不是为了避免闪断。
- `keep-alive` 的 `:include` 依赖 `tabs.cachedViews`，被删除菜单对应的缓存需由 `pruneInvalidViews(router)` 剔除（P6 实现；P3.5 阶段先调用占位空实现）。
- **「应用变更」的语义（决策 D4）**：本期**保存即写库并生效**，按钮只做「重新拉路由表 + 热替换」，**不调用任何发布接口**；生产环境才会出现「保存 → 发布」两步与「有未发布变更」提示（后端已预留 `publish_status` / `published_at`，见 `docs/11` §5.10）。
- 按钮文案保持「应用变更」，`hasDirty` 提示条文案：「有未应用的菜单变更，应用后即时生效」。

### 5.3 拖拽排序（`MenuTreeTable.vue`）

```ts
import { nextTick, onMounted, ref, watch } from 'vue'
import { useSortable } from 'vue-draggable-plus'

const tableRef = ref<InstanceType<typeof FsdTable>>()

function bindSortable() {
  const tbody = tableRef.value?.bodyRef // FsdTable 通过 defineExpose 暴露（docs/10 §2.2.1）
  if (!tbody) return
  useSortable(tbody, {
    handle: '.drag-handle',
    animation: 160,
    ghostClass: 'menu-row-ghost',
    onMove: (evt) => !isDescendant(draggedId, targetId(evt)), // 禁止拖到自身子孙
    onEnd: (evt) => {
      const payload = toMovePayload(evt) // { id, targetParentId, beforeId }
      if (payload) emit('move', payload)
      else restoreDom() // 非法目标：还原
    },
  })
}

onMounted(() => nextTick(bindSortable))
watch(
  () => props.tree,
  () => nextTick(bindSortable),
) // 树数据变化后重新绑定
```

- **绑定目标**：优先用 `FsdTable` 暴露的 `bodyRef`（`tbody` 元素），**不要**用 `.el-table__body-wrapper tbody` 选择器硬编码——那是 `el-table` 的内部结构，升级易失效。
- 绑定时机：`onMounted` + `nextTick`；`tree` 变化后重新绑定一次。
- 拖拽结束后**不直接改 DOM 结果**，而是发 `move` 事件交由编排层乐观更新 + 调后端，保证前后端一致。
- 后端 `order_no` 用**中间数插入**（`docs/11` §5.8），前端无需关心数值。
- `< 960px` 降级为「上移 / 下移」按钮（不绑定 sortable），见 §4.7。

### 5.4 层级上限校验（决策 D3 · `MAX_DEPTH = 3`）

双端一致，后端为准：

| 端                   | 行为                                                                                                                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 后端（`docs/11` §6） | 创建 / 移动时计算目标深度，`> 3` 直接 `422` 拒绝（常量 `MAX_DEPTH`）                                                                                                                                     |
| 前端                 | ① 3 级节点上「新增子级」按钮 `disabled` + `tooltip` 提示「最多 3 级」；② 拖拽 `onMove` 中预判目标深度，超限返回 `false`（显示禁止态）；③ 若仍收到后端 `422`，`ElMessage.error` 展示后端 `message` 并回滚 |

```ts
// features/menu-management/model/constants.ts
export const MENU_MAX_DEPTH = 3 // 与后端 MAX_DEPTH 保持一致（常量名不同，值必须相同）

export function depthOf(tree: MenuTreeNode[], id: number): number {
  /* 递归求深度 */
}
export function canAddChild(node: MenuTreeNode | null): boolean {
  return (node?.depth ?? 0) < MENU_MAX_DEPTH
}
```

> 前端校验只为体验，**不是安全边界**；后端校验不可省。两处常量值变更时必须同步（单测断言 `MENU_MAX_DEPTH === 3`）。

## 6. 接口对接（`entities/menu/api/menu.api.ts`）

```ts
export const menuApi = {
  list: () => unwrap(request.get<ApiResponse<MenuRecord[]>>('/menus')),
  tree: () => unwrap(request.get<ApiResponse<MenuTreeNode[]>>('/menus/tree')),
  create: (payload: MenuFormModel) =>
    unwrap(request.post<ApiResponse<MenuRecord>>('/menus', payload)),
  update: (id: number, payload: Partial<MenuFormModel>) =>
    unwrap(request.put<ApiResponse<MenuRecord>>(`/menus/${id}`, payload)),
  remove: (id: number, cascade = false) =>
    unwrap(request.delete<ApiResponse<{ id: number }>>(`/menus/${id}`, { params: { cascade } })),
  move: (payload: MoveMenuPayload) =>
    unwrap(request.post<ApiResponse<MenuRecord>>(`/menus/${payload.id}/move`, payload)),
}
```

错误码处理（`docs/11` §5.9）：`409` / `422` 的 `message` 直接透传给 `ElMessage.error`；`401` 由 `shared/api` 拦截器统一处理。

## 9. 风险与回退

| 风险                                       | 现象                   | 回退                                                                                                                   |
| ------------------------------------------ | ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `features → app` 向上依赖                  | 分层 lint 报警         | 组件注册表下沉到 `shared/lib/page-modules.ts`（本文档已采用）                                                          |
| `useSortable` 绑定表格 tbody 失效          | 拖拽无反应             | 数据刷新后 `nextTick` 重新绑定；或降级为「上移/下移」按钮（<960px 已用此方案）；必要时给 `FsdTable` 暴露 `bodyRef`     |
| 树形表格 + 拖拽的行索引换算错误            | move 后顺序错乱        | 统一用 `id` 计算 `beforeId`，**不使用** `evt.newIndex`（树形表格索引含折叠状态，不可靠）                               |
| 热替换期间当前路由缺失                     | 瞬间落 404             | **已定**：`applyRoutes` 内先注册后清理（`docs/13` §3.1）；禁止先 `clearDynamicRoutes` 再注册                           |
| 删除当前菜单后 keep-alive 残留             | 缓存页还能被切回       | `tabsStore.pruneInvalidViews(router)`（P6 落真实实现）                                                                 |
| 表单脏数据交叉污染                         | 切换行后字段串了       | 切换前 `isFormDirty` 提示；`form` 一律深拷贝                                                                           |
| `hasDirty` 两处持有（store 与 composable） | 提示条与实际状态不一致 | **已定归属 `menuStore`**：composable 内不建本地 `hasDirty`，一律读写 `menuStore.hasDirty / markDirty() / clearDirty()` |
